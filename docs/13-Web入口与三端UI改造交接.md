# 13 · Web 入口与三端 UI 改造交接

更新：2026-11-09。执行对象：Opus。UI01–03 已上线，当前任务使用本页第 0、9 节，[10 第 0 节](10-AI世界分阶段开发计划.md#0-当前发布路线)规定总体范围，[12](12-开发交接与进度.md)记录状态，[15](15-UI与同步并行开发约定.md)规定文件分工。其余章节保留上一轮设计，不表示需要全部重做。

## 0. 当前 UI 交付范围

近期主路线为“网页看效果 → DSH 安装 → 与房间角色互动 → 插件内放到桌面 → 创作分享”。独立桌面 App 是后续 R06，完整云同步与公共家具市场后置。Web 不要求先安装任何客户端，DSH 本地体验不要求注册公共账号。

| 入口 | 当前改造 | 验收重点 |
|---|---|---|
| GitHub / mu2a / 指南 | 展示真实效果、已验证的 DSH 安装方式、创作和反馈入口；沿用现有试玩 | 无空下载链接，无需先读长篇配置；未来能力明确标为计划 |
| DSH 房间 | 清楚呈现模型能力、“放到桌面”和返回内嵌房间 | 首次运行时准备有进度、取消/重试；下载失败仍能使用内嵌房间 |
| 桌面小窗 | 只保留场景与必要菜单；提供完整编辑、回 DSH、关闭桌面 | 拖动不误触家具，透明区域可穿透，气泡不遮挡主要场景；同一个家的接续由真实接口驱动 |
| 布置与分享 | 模板、导出/导入、登录分享及邀请分成短流程 | 本地保存位置可见；发布状态与公共收录状态分开；缺素材、失效邀请有明确下一步 |
| 身份与反馈 | 区分体验角色、自己的角色、模型在线状态；产品问题单独入口 | 不把离线台词称为模型回复，不把登录称为已同步，不把宠物情绪当成作者评分 |

房门继续左键直接通行、右键门旁气泡，编辑模式保留物件选择和拖动。面向新用户的主流程不再出现“旧社区”概念；历史数据与兼容代码保留。公共世界未来是连接区域，场景的文字页面是作品档案，不扩展普通自由回复论坛。

八种公开情绪、拒绝自由文本等规则按 10 的 R04b 由服务端实施后再接 UI；主人与自己 AI 的私人聊天另行保留。按钮隐藏不能算权限完成。未实现的桌面、云同步或投稿接口不允许显示成功状态。

Opus 先做上述页面/交互与状态表达，桌面辅助进程、模型桥、存档交接、权限和打包由架构负责人安排。共享文件一次只给一个负责者；具体范围见 15 第 0 节。以下第 1–8 节是上一轮设计背景，当前范围有差异时以本节与 10/12 为准。

## 1. 这一轮要交付的体验

用户访问 `https://mu2a.penguingugu.com/`，立即看到可操作的 2.5D 场景；可以先体验、照文档布置自己的房间，也可以注册/登录后直接去公共世界。收到朋友邀请时，打开链接、完成必要登录就能进入对应房间。安装 DSH 或 Electron 是使用宿主能力和桌面陪伴的选择，不是进入世界的前置条件。

普通玩家不需要安装 Node.js、启动服务、填写服务器地址、配置模型或创建自己的世界，才能进入公共场景。没有模型时仍可走动、互动、交流、完成活动并保存共同经历。模型接入是后续增强能力；离线角色行为必须如实标为本地行为。

公共家具分发和完整三端同步保留为后续方案。当前先完成安装、插件内桌面和最小创作分享；作品的文字档案记录内容、版本与访问状态，不将普通帖子讨论作为新主流程。

## 2. 当前事实与必须处理的问题

以下表格记录 2026-11-08 上线前的问题。后续 UI01–03 已发布到 mu2a，真实 GitHub 登录与公共入场已通过，不能把表中的旧 404/缺首页当成当前线上事实。具体完成情况见 12 的部署记录。

| 当前实现 | 用户遇到的问题 | 改造要求 |
|---|---|---|
| `deploy/town/Caddyfile` 全部代理后端；镜像主要装载服务模块 | 打开域名看不到场景 | 增加正式 Web 构建和静态资源路由；保留 API、认证及 SSE |
| `town.js` 默认连接 `127.0.0.1:18780`，失败提示运行本机服务 | 普通玩家以为必须部署服务器 | 正式 Web 使用同源服务；安装端带默认服务配置；自托管地址放高级设置 |
| `world-panel.js` 把加入邀请和创建活动放在一个长表单 | 想串门却看到信标、作者、许可等字段 | 加入、创建、作品管理拆成独立任务 |
| 社区页混合“AI 小镇本机原型”“帖子就是场景”“AI 世界” | 无法理解现在在哪、应点哪里 | 主入口统一为“世界”，旧帖子入口单列 |
| `/invite` 要复制链接，客户端还检查服务地址是否一致 | 邀请在登录、跨应用时断掉 | 保存待进入目标；登录完成后继续；服务切换有明确显示 |
| `roomkit-neutral` 是引擎候选，无 DSH 宿主入口 | 用户把引擎包当插件安装 | 分别交付引擎包、DSH 插件包、Electron 安装包；下载页明确区分 |
| 默认角色、本地台词、宿主模型和会话同伴并存 | 误以为已完整导入自己的 AI | 公开角色身份、模型连接、私有设定是否可用分别显示 |
| 三端存档分开，登录不会同步整个家 | 换端后像换了一个账号或宠物 | UI 接入 14 的账户与同步状态，不显示假的“已同步” |

已有房门交互必须保留：游玩时左键直接换房，右键门旁气泡；未连接的门仅短提示。不得恢复大幅遮挡场景的确认面板。布置模式保持选中/拖动语义。

## 3. 页面结构与场景布局

### 3.1 Web 首页

首页以正在运行的中性示例场景为主体，配少量说明和两个明确入口：“先体验”“去公共世界”。示例可以直接操作，先体验不要求登录。另提供“布置我的房间”“接入 DSH / 下载桌面版”“创作指南”。避免用整页介绍挡住场景。

- 未登录首次进入：使用本机试用角色，明确标为“体验角色”。不捏造在线玩家或后台模型回复，不自动创建服务器场次。
- 游客布置：从模板建立本地副本并自动保存；有“仅保存在此浏览器”和导出入口。存储不可用时明确提示临时体验，不能虚报保存成功。
- 登录用户进入：优先恢复该账号的家或上次明确选择的入口，不把新模板覆盖在已有家上。
- 公共世界入口：未登录可以看介绍、预览与开放状态；选择进入真实场次时登录，完成后继续目标。
- 无默认模型：保持游玩按钮可用，角色状态写“手动陪伴”或“本地自主活动”；“连接我的 AI”作为可选操作。

使用已整理的中性引擎和可分发内容。不要为得到与原版相同的画面，把 L1 排除的素材重新内嵌回来；发布素材与当前候选的来源范围单独核对。

### 3.2 四个主要入口

| 入口 | 首屏内容 | 次级操作 |
|---|---|---|
| 我的家 | 当前房间、主角、保存状态 | 布置、地图、房间管理、模板、导入导出 |
| 世界 | 公共交流空间、活动世界、朋友邀请 | 我的作品、开场、邀请、旧社区 |
| 家具 | 已拥有的家具、公共家具库 | 来源、固定版本、改编、提交分享 |
| 经历 | 与谁、在哪、共同做过什么 | 来源、角色感想、补领、导出 |

首屏只展示当前任务需要的操作。“服务器地址、模型供应商、素材许可、信标物件选择、同步冲突详情”等进入对应设置/创作步骤。未实现的家具服务必须显示明确状态，不把本地样例伪装为在线内容库。

桌面宽屏可使用小型侧面板；窄窗口使用可收起的底部面板。普通浏览和行走时，场景保持主要可视面积。菜单不因每次状态轮询反复重建而丢失焦点、滚动位置或正在填写的内容。

### 3.3 三端外壳

| 端 | 主用途 | 特有行为 |
|---|---|---|
| Web | 零安装体验、登录逛世界、基础布置、分享预览 | 同源连接；刷新和直接打开子路径可恢复目标；不扫描用户电脑或索取 DSH 凭据 |
| DSH 插件 | 连接用户已有模型、角色互动和场景创作 | 使用宿主模型适配器；插件入口与小窗共享状态；“Agent 操作房间”是独立可选授权 |
| Electron | 桌面常驻陪伴、完整房间窗口 | 小窗保持轻量；账户、编辑和冲突处理在完整窗口；关闭完整窗口前先完成本机保存 |

三端共享页面组件、数据状态和文案；宿主只提供窗口、模型、认证存储等适配。不要分别写三套世界业务。不要通过让 Electron/DSH 直接加载具有本机权限的远程页面来“实现同步”。

## 4. 必须打通的用户路径

### A. 游客先体验，再整理自己的房间

1. 打开 mu2a，场景出现并可交互，无登录遮罩。
2. 点击“布置我的房间”，复制模板进入本地草稿，摆一件家具、改颜色、保存。
3. 提供“创作指南”并直接定位到布置、家具格式或 AI 辅助创作示例；不用先阅读部署文档。
4. 用户选择“保存到账户”时才登录，并预览将保留的本地房间。登录成功只做一次明确的认领，不覆盖同账号已有存档。

指南至少提供：五分钟布置示例、房门连接、家具占地与交互位、导入导出、AI 可生成的标准数据示例及校验错误解释。让 AI 修改草稿后先预览差异，公开分享仍由用户发起。

### B. 注册/登录后去公共世界

1. 首页或“世界”选择一个开放场景，点击“进入”。
2. 未登录则展示已开放的登录方式。首版复用现有 GitHub OAuth；首次登录创建账号，已有账号直接登录，不额外建立一套密码注册。其他供应商仅按服务端能力显示。
3. 已有角色默认选择上次角色；首次账号使用中性角色和可修改昵称，基础游玩不要求填写人设或模型。只确认必要的公开信息。
4. 自动分配/加入有空位的场次，直接进入。第一次界面提示只解释移动、互动、回家。
5. 无模型可手动参加；有模型的客户端可开启 AI 行动。活动结束保存事实，感想可稍后生成。

默认允许正常注册用户进入已开放的公共世界；发言、上传和公开发布有各自权限与额度。若运营暂时关闭注册/入场，应直说开放状态并保留游客体验，不能让用户无休止填写配置。

公共世界是内容与场次的组合，不是所有人永久连接同一房间。达到人数上限时明确“这场已满”，允许加入下一场或返回目录；有上限时不无限创建新场。

### C. 进入朋友的房间

1. 点击邀请链接，打开带世界标题、房主、到期/可用状态的邀请页。继续兼容已有 `/invite#roomkit-invite=...` 链接；片段不应写进访问日志或分享统计。
2. 点击“进入房间”；必要时登录。保存目标和选择的角色，登录返回后继续，不要求再复制一次邀请码。
3. 同一账号重复打开自己的已兑换邀请，可恢复原场次；另一账号不能重复兑换一次性邀请。
4. 邀请过期、撤销、满员、场次结束、被移除分别显示原因和“返回世界”入口，不做无限重试。
5. DSH/Electron 支持粘贴完整链接后自动识别服务和目标。对已有默认服务无需再配置；指向其他服务时，先展示服务来源，再使用该服务自己的登录，绝不转发原服务令牌。

“在 DSH/桌面端打开”可渐进实现。宿主没有经过验证的唤起能力时，保留一次粘贴链接的明确替代路径，不把调用不存在的自定义协议算作成功。Web 内进入朋友世界的完整流程不依赖应用唤起。

### D. 创作世界和分享家具

创建世界从“我的家 → 发布为世界”发起：预览 → 名称和封面 → 选择开放方式/活动预设 → 发布。只有选择活动后才展开信标等规则参数；第一次提供可直接运行的活动模板。

分享家具从“选中家具 → 分享”发起，预览仅含所选家具及必要依赖的内容包。发布、获取、固定版本、改编来源、审核与下架状态按 W12 的家具分发子任务实现，禁止把任意完整内容包无筛选地当公共家具导入。获取成功显示“已添加到我的家具”，不会自动修改公共世界布局。

公共世界放置家具由该世界维护者管理。普通用户的分享进入公共家具库和待展示候选；“可下载”和“可修改公共世界”分别授权。世界布置更新发布新版本，正在活动的旧场次继续固定原版本。

## 5. 状态和错误怎样表达

| 状态 | 用户能做什么 | 应显示的内容 |
|---|---|---|
| 游客 | 体验、布置本地副本、看公开目录 | 体验角色；仅保存在此浏览器 |
| 登录成功，未开账户同步 | 进入公共世界/受邀世界 | 已登录；本地房间未上传 |
| 账户房间 | 保存并跨端继续 | 已保存 / 等待联网 / 有修改待处理 |
| 无模型或模型超时 | 继续手动移动、互动和交流 | 手动模式；稍后连接 AI，不阻断入场 |
| 另一端控制中 | 看见同一角色与场次；选择接管 | 正由另一设备控制；在这里继续 |
| 服务不可达 | 本地体验、编辑、导出 | 世界暂时连不上；保留本机内容并提供重试 |
| 注册/入场受限 | 游客体验、阅读说明 | 当前开放条件，不误报网络错误 |
| 资源不兼容或家具被隔离 | 看具体原因，保留旧副本/安全占位 | 缺少哪个版本、如何处理，不静默换成另一件家具 |
| 登录取消或过期 | 重试并继续原目标 | 邀请和未提交草稿保持，不重新走教程 |

登录失败与模型失败分开；模型连接与世界连接分开。同步完成必须得到服务器确认。本地保存失败不能仍显示“已保存”。创建者、玩家、审核员看到不同操作，权限最终由服务端检查。

## 6. 服务端与部署配合

### 6.1 同域 Web 入口

部署应形成以下职责，具体由 Caddy 或受限静态服务实现：

| 路径 | 职责 |
|---|---|
| `/` 和受支持的页面路径 | Web 场景外壳与路由恢复 |
| `/assets/...` | 带版本/内容摘要的公开引擎与示例静态资源 |
| `/api/...`、`/auth/...` | 既有业务与登录；保持 JSON/认证错误语义 |
| `/events`、`/world-events` | 原有 SSE；保持及时转发 |
| `/invite` | 正式邀请落地页；保留旧链接解析 |
| `/health` | 原有健康检查 |
| `/docs/...` 或明确的文档链接 | 面向用户的布置与安装指南 |

不能让 SPA 回退把 `/api` 的 404/401 变成 HTML，也不能把数据库、环境文件、源码工作目录当静态根目录。正式站点默认服务为同源；本机开发地址只在开发配置出现。入口文档短缓存、带摘要资源长缓存；构建记录固定引擎、内容和协议版本，并具备回滚方式。

### 6.2 最小新增接口

以下是拟议接口，不是现成能力。沿用 `/api/{name}` 风格即可，不必换传输框架。

| 拟议接口 | 输入/结果重点 | 权限与边界 |
|---|---|---|
| `publicConfig` | 服务标识、可用登录方式、是否开放注册/公共入场、协议能力、默认公共世界 | 只返回公开配置，不返回任何凭据 |
| `publicWorldList` | 分页目录、简介、预览引用、开放/满员状态 | 只显示明确公开且可展示的固定版本；不列私人草稿 |
| `publicWorldGet` | 公共预览所需的固定版本和素材清单 | 预览不获得成员身份，也不暴露真实场次聊天或角色私有信息 |
| `publicWorldEnter` | 世界、选定角色、幂等请求；返回实际场次 | 登录后事务内检查开放条件、封禁、容量和现有成员资格，再复用 `worldJoin`；不能发一个全员共用邀请码 |
| `invitePreview` | 邀请对应的最少展示信息和状态 | 限频、只读、不兑换；私密邀请仅持有者可预览，敏感信息不公开索引 |

现有 `config` 可以扩展公开字段，不必重复制造配置源。公共入场必须真实实现权限与容量判定；前端放一个“公共广场”按钮或借用旧帖子场景不等于完成。

未登录预览只运行本机展示副本，不订阅真实场次或消耗公共 AI 调用。真实公共场次继续使用人数上限、无人暂停、事件限额和模型预算。公共目录不能把所有家具图片塞进每次轮询响应。

| 任务 | 产出 | 主要改动入口 | 依赖 |

Opus 主责为用户流程、页面实现和这条流程不可缺少的最小接口。完整同步按 14 拆任务，不在 UI 改造中偷偷实现整库复制。若另一位开发者负责服务端/同步，先确定文件负责人；`town.js`、`world-panel.js`、`src/client.js` 等共享文件同一时间只能由一方修改，最终统一集成。本文不要求自动启动并行代理。

UI01–03 优先于完整三端同步和家具市场；Web 用户不应等 Electron 打包完成才能体验。不得仅交付静态设计图或带假数据的按钮就标记用户流程完成。

## 8. 验收清单

- [ ] 全新浏览器访问 mu2a 首页返回正常页面，看到可操作场景；不安装软件、不注册、不填地址、不配模型。

- [ ] 从公共世界卡片发起登录，回来继续原目标；没有模型仍能与另一真实账号移动、互动、交流。
- [ ] 直接打开邀请链接即可在 Web 进入目标；取消登录、过期、撤销、重复兑换、满员均有正确结果。
- [ ] 没有朋友邀请也可以进入已开放公共世界；公开浏览不会暴露私密世界、场次聊天或人设。
- [ ] 布置与游玩分开；左键房门直接通行、右键气泡操作；390px 窄窗口和 DSH 小窗不被常驻大面板遮住。
- [ ] 新账号角色身份可继续使用；页面明确哪些私有设定尚在另一设备，不冒充完整 AI 已迁移。
- [ ] API/认证/SSE 路由不被静态首页劫持；刷新子页面、资源缺失、服务故障都能解释与恢复。

- [ ] 未接入的同步、家具审核或远端 AI 功能不显示虚假的成功状态。

交付时记录真实新用户操作数与耗时。目标：进入 Web 即可体验；从“进入世界”到入场只保留必要登录/角色确认，已登录且有角色时一次点击。网络、首次供应商授权和下载耗时单独记录；不把目标写成已达到的性能结论。
