## 一、目标与设计原则

**目标**：DeepSeek 角色卡的鲸鱼娘「大肥鱼」有一个能布置、会自己过日子、有剧情的 2.5D 家；
同一套引擎跑在独立网页、DSH 插件、桌面窗口三处；DSH 里她跟着你的工作状态忙前忙后、能聊天、能被 Agent 驱动；
后期多只大肥鱼可以互相串门聊天，网友分享家具/房间/剧情，形成内容生态。

**原则**（从参考站与同类产品的经验提炼）：

1. **3 秒内看到能点的东西**：首屏必须有菜单（Dock）和引导；物件即按钮（悬停高亮 + 名牌）。
2. **镜头只听用户的**：剧情、事件不自动推镜头/弹全屏——一律先给「❗ 提示条」，用户点了才演（Fallout Shelter 玩家最反感自动缩放）。
3. **平移和操作分开**：拖动 = 平移画面，点 = 互动/走过去；不要求拖拽角色。
4. **一切操作都是命令**：UI、插件、模型工具、联机对端都调用同一个 `app.command(op)`；场景编辑都走 `world.apply(op)`（可撤销、可同步）。
5. **内容是纯 JSON**：家具/场景/剧情/角色卡/家（多房间）都可导出分享，导入白名单校验，不含代码。
6. **安全边界清楚**：会花钱的（调模型）、会改系统的、会开网络的，要么走 DSH 鉴权通道，要么交给用户手动操作。

参考站 jolly-small-plays 的可借鉴点（读过其源码 `js/main.js`）：
楼层按钮 B1/1F/AL/2F + 表盘指针、切楼层时「关门 → 换场景 → 开门 + 叮」、大号楼层闪字、数字键 1–4 切楼层、
每层一章（CH.01 · 地点 · 时钟 · 标题）、每层一件证物的收集进度 0/4、底部时间轴章节标记、SOUND/THEME 开关。

## 三、多场景：「家」

### 3.1 模型

```jsonc
// storage.pref('home')；内容包也可以带一个默认的家（pack.home）
{
  "v": 1, "name": "大肥鱼的家",
  "floors": ["2F", "1F", "户外"],                      // 显示顺序（上 → 下）
  "rooms": [
    { "id": "home",   "name": "卧室", "floor": "2F", "tpl": "default|home" },
    { "id": "living", "name": "客厅", "floor": "1F", "tpl": "default|living" }
  ],
  "follow": true                                     // 带「跟随」标记的角色跟着你换房间
}
```

- 房间 = 一个普通场景（`roomkit.scene`），`id` 就是场景 id；没存过的房间按 `tpl` 从模板现生成（首次进入才写存档）。
- 旧存档迁移：已有的 `home` 与「从客厅模板建的场景」自动认领为家里的房间，不重复生成。
- 不在家里的场景（以前建的副本、导入的场景）在地图里单列，可「加入家」。

### 3.2 门 = 传送门

- 门的状态 `state.to = 房间 id`。点门：抽屉显示「通往 客厅」→「走过去」：主角走到门口、门打开 → 转场 → 在对面房间对应的门口出现。
- 没连的门：抽屉里列出家里的房间，点一个就连上并过去（不用进布置模式）。默认家的卧室门 ↔ 客厅门预先连好。

### 3.3 跟随与驻留

- 角色记录上的 `follow: true`（主角 `brain: 'pet'` 默认跟随）= 跟着你换房间：离开时从旧房间带走，进入时去掉新房间里同一角色的重复记录，在入口门旁出现。
- 其余角色驻留在自己的房间。「⋯ → 角色跟着我换房间」可整体关闭（回到每个房间各有一份角色的旧行为）。
- 跨房间保留：需求值随角色带走；DSH 工作状态在新房间重新套用（切房间不会丢「干活中」）。
- 以后（P3+）：驻留角色按作息在房间之间自己走动，不在当前房间的角色做低频后台模拟。

### 3.4 切换体验

转场幕布（两扇门合上 → 换场景 → 打开，约 0.7 秒）+ 楼层闪字「1F · 鲸鱼客厅」+ 叮（开声音时）。
入口：房间下拉、房间条、地图卡片、数字键、过门。

### 3.5 地图页（楼层平面）

按楼层分组的房间卡片：等距缩略图（按场景 JSON 画，含家具块与角色点）、名字、「你在这里 / 大肥鱼在这」、剧情进度 1/2；
下方「不在家里的场景」「添加房间（模板 / 空房间 / 露天广场，加到当前楼层）」；卡片 ⋯：改名 / 换楼层 / 移出家。

### 3.6 默认内容（P3）

卧室（2F）、客厅（1F）、厨房（1F）、小院（户外）……每个房间 1–2 段剧情；大场景（40×40 庭院）做静态层缓存与视野裁剪。

## 四、DSH 插件交互

### 4.1 入口（已完成，见 docs/06）

右下角小窗（默认开，可收成胶囊，`Alt+Shift+R`）· 右侧栏标签 · 全屏 · 插件页（入口说明 + Web 预览链接）· 旧版设置页。
同一时刻只挂一个房间实例；切换载体前先存档。

### 4.2 宿主半侧服务

| 服务 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| 静态页面/素材 | `/plugins/dsh-room/web/*` | 公开（只读） | Web 预览、真模型贴图 |
| 存档 | `/plugins/dsh-room/api/store` | 本机来源校验 | 多端共享同一间房；拒绝非本机 Host / 跨源 Origin（防 DNS 重绑定） |
| 预览信息 | `/plugins/dsh-room/api/info` | 本机来源校验 | 只返回本机地址，不含凭据 |
| **RPC 通道** | `dsh-room/<endpoint>` | **DSH 浏览器鉴权**（`ctx.connection.rpc`，与 DSH 自己的 `/api` 同一道 Host/Origin 栅栏 + 会话 Cookie；桌面版走 IPC） | `status` 工作状态 · `chat` 对话 · `poll` 取 Agent 下发的命令 · `tools` 工具开关 |

会花钱（调模型）和能驱动房间的接口**只走鉴权 RPC**；Web 预览页没有 DSH 凭据，自动降级为离线模式。

### 4.3 工作状态（不再依赖 dsh-pet）

宿主监听 `session/event`，按 dsh-pet 的状态机压缩成六档：
`turn/start → thinking`，`tool/call → working`（`ask_user_question` → waiting），`tool/result → result`，`approval/asked → waiting`，
`turn/end`：completed → success，error/max-tokens/timeout → error，blocked → waiting，其余 → 清空回空闲；`todo/write` 只更新任务文案。
按会话聚合，展示优先级 waiting > error > working > thinking > result > success；完成/出错 8 秒后自动回空闲。
页面每秒取一次 `status`：主角跟展示态走；开了「会话同伴」时每个会话一只小鲸鱼跟自己的会话状态走。dsh-pet 在时作为第二来源。

### 4.4 外壳扩展点（`opts.ext`，引擎不认识 DSH）

`ext.host`（运行环境名）· `ext.connection()`（连接灯）· `ext.diagnostics()`（连接页检查项）· `ext.social`（社区页开关：会话同伴、Agent 工具）·
`ext.chat(req)`（对话）· `ext.openFull()`（全屏）。网页版不传就是纯本地模式。

### 4.5 对外接口

页面内 Cordis 服务 `roomApi7341`：`command(op)`、`on(fn)`、`open()`、`app`——同页其他插件可直接驱动房间。

## 五、DS 交互

### 5.1 和她聊天

- 页面「💬 聊天」→ RPC `chat`：宿主用**当前对话的模型**（`agentDefaultModel`，模型声明支持时关掉深度思考），
  系统提示 = 角色卡人设（persona/scenario）+ 房间此刻的样子（时间天气、谁在做什么、有哪些家具、家里有哪些房间）+ 回复规则（口语、≤ 60 字、可选一个动作标记）。
- 回复里的动作标记 `[[wave]] [[dance]] [[sleep]] [[read]] [[goto:家具]] [[use:家具]] [[room:房间]] [[emote:符号]]` 被剥掉并执行：
  说「去睡觉吧」→ 她回一句并走去床上；说「去客厅看电视」→ 她穿门去客厅（跟随时镜头一起过去）。
- 限制：单句 ≤ 300 字、历史 ≤ 12 条、同时只跑一个、每分钟 ≤ 20 次、45 秒超时；失败返回原因，不静默。
- 网页版 / 没接模型：离线台词规则（关键词 → 动作 + 角色卡台词）。

### 5.2 让 DSH 里的 Agent 驱动房间（默认关）

社区页「允许 Agent 操作房间」打开后，宿主注册三个工具（关掉即注销；会进入每个对话的工具清单，所以默认关）：
`room_look`（房间描述）、`room_say`（让角色说一句）、`room_do`（动作：wave/dance/sleep/read/goto/use/room/emote）。
命令进宿主队列，页面轮询执行；房间没打开时工具如实返回「房间没有打开」。

### 5.3 主动行为

工作状态联动（已有）；会话同伴（每个会话一只小鲸鱼，点它打开该会话）；以后：模型生成的碎碎念（默认关，花钱）。

## 六、社区与社交（服务器）

目标：多只大肥鱼互相串门、聊天；网友分享家具/房间/剧情；形成内容生态。

### 6.1 架构

```
 浏览器 / DSH 插件 / 桌面窗口（每只大肥鱼的「大脑」都在主人本机）
        │  JSON 消息：与 app.command / world.apply 同一套 op
        ▼
 ┌──────────── roomkit-server ────────────┐
 │ 房间：房主权威，服务器存最新快照 + 转发   │
 │ 大厅：在线列表、串门邀请、好友            │
 │ 内容广场：上传、校验（复用 packs.js）、索引 │
 │ 账号：设备 id 起步 → OAuth                │
 └────────────────────────────────────────┘
```

### 6.2 协议（草案）

| 方向 | 消息 | 说明 |
|---|---|---|
| → | `hello { v, me:{ id, name, look, char } }` | 连接 |
| → | `open { room:{ id, name, scene }, visibility }` | 房主开放房间（好友 / 链接 / 公开） |
| → | `join { room, agent:{ name, look, character } }` | 访客带着自己的鲸鱼进门 |
| → | `op { room, op }` | 只有房主：场景编辑 |
| → | `cmd { room, cmd }` | 访客只能控制自己的角色（goto/say/emote/pose） |
| → | `chat { room, text }` · `leave { room }` | |
| ← | `room { id, scene, members, rev }` | 进门时的完整快照 |
| ← | `op / cmd / chat / presence { from, rev, … }` · `error { code, message }` | 广播 |

单条 ≤ 64KB、每连接 ≤ 10 条/秒、op 白名单同内容包校验；房间列表用「快照 + 失效通知」，不轮询、不为列表进房间（roomlab 的做法）。

### 6.3 多只大肥鱼互相聊天

房主端当「导演」：两只空闲的鲸鱼凑到一起时，给其中一只的主人端发「轮到你说」（话题 + 最近几句）；
主人端用**自己的** DSH 模型生成一句（人设 + 对话片段）回传；每段 ≤ 6 句、冷却 2 分钟、主人可关「让我的鲸鱼和别人聊天」。
服务器只转发文字，不持有任何人的模型 key，也不产生模型费用；没接模型的鲸鱼用离线台词聊。

### 6.4 分步

| 步 | 内容 | 谁做 | 状态 |
|---|---|---|---|
| S1 | 本机多标签同步（BroadcastChannel）：同一间房两个窗口实时一致——验证 op 流同步 | 我 | P2 |
| S2 | `server/` 本地中继原型（只用 node:http，SSE 下行 + POST 上行，只监听 127.0.0.1）+ 串门 UI：两个浏览器互访、鲸鱼互聊（离线台词版） | 我 | P3 |
| S3 | 内容广场：GitHub 仓库 + `index.json` 目录（参考 aboutme-pets 的 `pets.json`），PR 提交 + CI 用 packs.js 校验；应用内浏览/一键安装（目录地址由用户在设置里填） | 我写代码与 CI；仓库由用户建 | P3 |
| S4 | 公网服务：服务器、域名、TLS、备案、账号、审核、隐私政策 | **用户**（我出部署文档与检查清单） | P4 |

### 6.5 选型与成本（S4 时由用户定）

| 方案 | 优点 | 注意 |
|---|---|---|
| Node 单进程 + SQLite + Caddy（VPS） | 可控、便宜、协议就是 S2 原型 | 运维、境内需 ICP 备案 |
| Cloudflare Workers + Durable Objects（PartyServer） | 一房一对象、WebSocket 休眠省钱、免费额度 10 万请求/天 | 境内访问可能慢 |
| Colyseus（MIT） | 自带房间/状态同步/匹配 | 多一层框架 |

### 6.6 安全与合规（上线前必须完成）

- 内容：白名单 JSON + 内嵌图片（已有校验），服务器二次校验、尺寸限制、举报/下架、敏感词。
- 聊天：频率限制、屏蔽/拉黑、房主踢人；默认只允许好友串门。
- 隐私：不上传 DSH 会话内容；工作状态只同步档位（思考/干活），任务文本默认不同步。
- 许可：大肥鱼/女仆素材 CC BY-NC-SA（非商用），Coopanion 真模型 AGPL——社区站必须非商用并标注署名；用户上传需声明许可。
