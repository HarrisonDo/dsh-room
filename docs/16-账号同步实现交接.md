## 1. 模块接口

- `scripts/account-store.mjs` 的 `createAccountStore({ db, q, tx })` 使用小镇同一个 SQLite 连接、语句缓存和同步事务。初始化在旧表迁移之后执行，创建 `account_defaults(account_id, character_id)`。复用 `accounts`、`members` 和账号封禁记录。旧角色删除或转属后，下次 bootstrap 重新核对默认指针。
- `scripts/account-service.mjs` 的 `createAccountService({ store, authenticate })` 返回两项同步处理器，签名均为 `(payload, context)`。同步认证回调 `authenticate(context)` 返回当前有效的账号 ID 或空值，可沿用宿主的 HTTP 认证错误。认证、读取、初始化和选择在同一个写事务内完成。单进程的同步事务天然串行，多连接部署应沿用宿主的 SQLite 等锁配置。
- `shared/account-identity.js` 提供 `accountOrigin(service)`、`accountScope(service, accountId)` 和 `characterIdentity(service, accountId, characterId)`。只接受无路径、查询、片段及认证信息的 HTTP(S) 来源。账号存储键是 JSON 编码的来源与账号 ID 二元组，角色稳定身份增加服务端角色 ID。
- `web/roomkit/account-client.js` 的 `createAccountClient({ storage? })` 提供 `switchAccount({ service, accountId, request })`、`bootstrap()`、`selectDefaultCharacter(characterId)`、`snapshot` 和 `clear()`。适配器 `request(method, payload, { signal })` 必须绑定该来源和该登录会话，凭据由适配器持有。宿主应使用认证结果提供的账号 ID。切换时立即清空当前快照并中止旧请求，迟到结果返回 `null`。同一代只允许一个在途请求，完成或失败后可重试。可选同步存储 `storage.set(scopeKey, characterId)` 只写按账号隔离的选择提示，默认角色以服务器为准，提示不会被用作身份恢复依据。

## 2. HTTP 契约

两个接口均为 `POST /api/<方法名>`，沿用小镇 JSON 与 Bearer。bootstrap 首次为没有任何角色的正式账号创建中性角色。有角色时保留旧昵称和外观。没有有效默认指针时选最早创建的角色，同时间按 ID 排序。显式选择同一个角色可安全重试。并发选择不同角色时，以服务端最后提交的选择为准。下面示例为独立模块启用资源时的返回，当前公开服务的 `homeSnapshots` 为 false，不将示例当作线上功能声明。

`POST /api/accountBootstrap` 的请求体为 `{}`。`POST /api/accountSelectDefaultCharacter` 的请求体例如 `{"characterId":"c_example"}`。两者响应同形：

```json
{
  "account": { "id": "gh:42", "provider": "github", "name": "示例账号" },
  "characters": [{ "id": "c_example", "name": "角色", "kind": "girl", "look": {} }],
  "defaultCharacterId": "c_example",
  "capabilities": {
    "identity": true,
    "defaultCharacter": true,
    "homeSnapshots": true,
    "assetValidation": false,
    "resourceSync": false,
    "deviceSessions": false
  }
}
```

`homeSnapshots` 表示账户家快照接口可用。`assetValidation` 表示已接入素材依赖验证器。能力字段描述服务端接入能力，单次保存的结果仍以请求响应为准。完整同步和设备管理尚待接入，`resourceSync` 与 `deviceSessions` 保持 false。账号来自认证上下文。请求中的 `accountId`、昵称和外观没有作用。响应只投影账号标识、显示名、供应商与公开角色字段，外观复用 `publicLook`。凭据、旧角色 key、私有人设和模型能力均不在返回契约内。

未登录、令牌失效或账号不存在返回 401。封禁返回 403，错误码 `account_banned`。越权选择返回 403，错误码 `character_forbidden`。无效的角色标识返回 400，错误码 `invalid_character`。客户端适配器应保留 HTTP `status` 和服务错误 `code`，旧角色选择越权保留现有身份，登录失效或封禁清理当前快照。

## 3. 既有入口最小接入

以下片段是独立模块交付时的接入说明。身份处理器与 Web 接线现已完成，不要重复增加；当前正式入口显式关闭资源处理器，恢复完整同步前需完成素材与页面接入。下列示例未指定 `enableResources`，不能直接用它替换线上配置。

1. 在 `town-store.mjs` 导入 `createAccountStore`，在旧表和 `q/tx` 准备好后初始化，将独立实例挂到现有返回对象的 `accountStore` 字段。

   ```js
   const accountStore = createAccountStore({ db, q, tx });
   // 现有 openStore 返回对象中添加 accountStore
   ```

2. 在 `town.mjs` 的 `createTown` 内，定义完 `who` 后创建处理器。在现有 `api` 对象中展开 `...accountApi`。明确要求 Bearer，保持现有正式认证和过期检查，隔离旧原型 me/key。现有 `serve` 已按 API 对象路由，无需单写 HTTP 分支。

   ```js
   const accountApi = createAccountService({
     store: store.accountStore,
     authenticate: (ctx) => ctx?.token ? who({}, ctx).acc : null,
   });
   ```

3. Web、DSH 和 Electron 各自由可信的登录结果初始化同一个客户端模块。接入 `town.js` 的账号确认流程时，先完成身份读取与角色恢复，再开放认领、改名或外观提交。不要让现有 `Town.connect()` 的本机模板上报抢在 bootstrap 前。进入场次时将 `identity.characterId` 交给既有角色归属及租约检查。退出、切换来源或切换账号时先清理客户端，再由宿主结束旧控制与凭据。
4. 发布接入版本时由负责人核对容器的脚本复制清单和独立 npm 白名单。仅在新的源码入口接通后重建对应产物。

## 5. SYNC02 账户家接口

`createAccountStore({ db, q, tx })` 现在返回 `resources`。它先调用 `migrateAccounts({ db, q, tx })`。迁移 1 保留首批已存在的 `account_defaults`，迁移 2 建立当前快照与回执表。迁移版本写入 `account_schema_migrations`，和建表一起提交，重启可重复初始化。初次备份请继续沿用现有 SQLite 备份路径。

同一个 `createAccountService({ store, authenticate, validateDependencies? })` 自动提供以下处理器。鉴权、作用域查询、条件比较、依赖确认、写入和回执都在同一个同步事务内。请求不接受账号 ID，查询按服务端认证账号限定。资源 ID 是账号内标识，同名 ID 可在不同账号各自新建。

| POST 路由 | 请求 | 成功响应 |
|---|---|---|
| `/api/accountResourceList` | `{}` | `{"resources":[{"resourceId":"home-1","syncVersion":1,"deleted":false}]}`，含墓碑 |
| `/api/accountResourceGet` | `{"resourceId":"home-1"}` | 同一资源的三项元数据及 `payload`，墓碑仅返回元数据 |
| `/api/accountResourcePut` | 下例，新建版本为 0 | `{"resourceId":"home-1","syncVersion":1,"deleted":false}` |
| `/api/accountResourceDelete` | 同一封套，省略 `payload` | 元数据，版本递增，`deleted:true` |
| `/api/accountResourceRestore` | 同一封套，省略 `payload` | 元数据，版本递增，`deleted:false` |

```json
{
  "format": "roomkit.account-resource",
  "schemaVersion": 1,
  "kind": "home",
  "resourceId": "home-1",
  "baseVersion": 0,
  "mutationId": "0:deviceGeneratedNonce",
  "payload": {
    "format": "roomkit.account-home",
    "schemaVersion": 1,
    "homeId": "home-1",
    "name": "我的家",
    "floors": ["1F"],
    "rooms": [
      {"id": "study", "name": "书房", "floor": "1F", "layout": {"room": {"w": 6, "h": 4}, "objects": []}}
    ],
    "assetRefs": []
  }
}
```

每次新修改生成 `<baseVersion>:<随机标识>`，超时重试发送相同请求。回执按账号、资源和操作 ID 隔离，保存规范化请求的 SHA-256 与原结果。同 ID 修改内容返回 `mutation_reused`。每家保留最近 64 次成功回执，超窗的旧基线返回 `mutation_expired`，调用方重新读取并处理冲突。版本从不重置，墓碑保留快照并占用每账号 32 个家的额度。本批保留当前快照、墓碑及回执，无通用历史版本读取、永久删除或垃圾回收。

冲突、过期、状态不匹配、额度和依赖错误使用 409，分别为 `version_conflict`、`mutation_expired`、`resource_state_conflict`、`resource_quota`、`missing_asset` 或 `unsupported`。未见本账号资源返回 404 `resource_not_found`，外部账号资源同样处理。未知格式、非法字段和不匹配的素材清单返回 400，快照超 256 KiB 返回 413 `resource_too_large`。冲突错误内部有 `currentVersion`，现有路由只透传 `error/code`，首轮客户端可调用 get。登录和封禁沿用第 2 节。

## 6. DTO、素材验证和接入边界

- `shared/account-resource.js` 中 `projectAccountHome({ homeId, home, sceneFor, assetRefs })` 从 `home.js` 的家元数据和每间 v2 场景投影可预览 DTO。缺失场景、房间 ID 不符或不支持的布局报错。仅取场景的 `room` 与 `objects`，保留 `state.to`。场景角色、人设、故事、临时环境、聊天和偏好均留在设备。后续界面须先展示预览，再按用户选择保存。
- 服务端独立用 `validateAccountHome(raw)` 严格检查未知字段。每家 1–24 间房、最多 1200 个物件，每房最多 400 个物件。允许空房，地板、墙壁和户外标记按固定字段验证。物件保留位置、朝向、最多 24 个受限颜色键、0–7 的换色预设索引，以及 `to/on/open/curtain/working/text`。海报文字限 120 字，作为显示文字而非资源地址。其它状态与扩展布局需明确迁移后再存。房间 ID 支持 `包/场景`，所有非空门目标必须存在于同一家。DTO 无图片、外链或任意嵌套状态。
- 每个使用的家具定义都要有唯一 `{def, assetId, version, hash}`，hash 为小写 SHA-256。同步注入 `validateDependencies({ accountId, home })`，须核对每个固定版本与摘要、授权和依赖完整性，以及颜色键和预设索引与定义一致、带非空 `state.to` 的物件确为可用门。只有显式返回 `true` 才能写入或恢复。未接入则返回 `unsupported`，返回其他值则为 `missing_asset`。素材库、上传、读取授权与 GC 尚待接续。夹具的许可回调只验证该接缝和失败回滚。
- 接入沿用第 3 节的 `...accountApi`，无需新增单独 HTTP 分支。宿主在素材授权实现前可验证空家具家。客户端同步队列和冲突副本的独立核心见第 8 节，宿主存储与页面仍待接入；别让旧整份存档直接调用 put。

## 8. SYNC03 无界面客户端核心

`web/roomkit/sync-client.js` 导出 `createHomeSyncClient({ storage, mutationNonce? })`。按服务来源、已认证账号及资源 ID 的 JSON 三元组隔离。该模块只处理已投影的账户家 DTO，宿主保管凭据、负责确认登录身份。每次切服务、切账号、换资源或退出都清除旧视图并中止旧请求。迟到响应不会提交给新账号，也不会更新新视图。

| 方法 | 宿主调用时机 |
|---|---|
| `open({ service, accountId, resourceId, request, create? })` | 登录或打开资源时载入本机记录。请求适配器绑定当前服务和会话，签名为 `request(method, body, { signal })`。只对用户明确新建的稳定 ID 使用 `create:true`，此时无基线可显式设为 0，既有正版本不重置。 |
| `pull()` | 首次打开既有账户家，或在草稿干净时刷新。404 交给界面区分尚无记录和旧版本不可达，不自动创建。 |
| `edit(home)` | 传入通过 SYNC02 DTO 约束的家。持久事务确认后才能显示本机已保存。 |
| `flush()` | 网络可用或用户重试时提交一次。一次最多推进一个请求，收到回执后如仍有新编辑，再调下一次。 |
| `forkLocalCopy(copyId)` / `adoptRemote()` | 明确处理冲突。先另存到新的本机 ID，再按用户选择采用账户版。副本没有账户基线，后续明确新建才上传。墓碑可作为账户版采用，账户恢复另走显式 restore 接口。 |
| `snapshot` / `clear()` | 读无外部引用的状态快照，或在退出时释放当前上下文。 |

`snapshot` 中 `baselineVersion` 是最后确认的账户版本，`null` 表示尚无基线，0 表示明确新建。还有 `deleted`、本机 `draft`、`dirty`、带固定 `baseVersion/mutationId/payload` 的 `pending`，以及 `conflict:{reason,remote}`。冲突的 `remote` 可以是账户版本、墓碑或确实未能取得资源时的 `null`。服务端回执会核对资源 ID、版本与删除状态，GET 快照还验证格式和布局。账号隔离以绑定认证适配器为主，响应带账号字段时额外核对。

未确认提交先落本机再发送，断网和丢回执都重用原请求。A 发送后又保存 B 时，A 的回执只推进基线，B 继续等待提交。远端冲突不会自动覆盖。每实例同一上下文只运行一个网络操作，跨实例即使重发已持久化的同一请求，也使用同一操作 ID。前端仅用 `synced` 显示确认状态，`localSaved` 只描述已持久化的草稿。清理当前视图保留旧作用域的持久队列。

### 持久适配协议

- `get(key)` 返回 `{key,revision,state}` 或空值，可同步或异步。只读取这个键。
- `compareAndSet(key, expectedRevision, record)` 原子比较并替换，提交完成后返回 `true`，基线不同返回 `false`。不存在的记录用 `null` 作为期望版本。每次写入的新本机 revision 加一，与账户版本无关。IndexedDB 适配需在同一读写事务完成读、比较、写，并在事务提交后确认。存储拒绝时不得部分写入。
- 错误的 `kind` 区分 `storage`、`storage_conflict`、`request` 和 `protocol`。请求适配器须保留服务器业务错误 `code` 或 `reason`，以及原始 HTTP 状态。宿主收到登录失效或封禁时联动身份清理。账户版本冲突以快照返回，和本机 CAS 冲突分别提示。
- 同一存储上的其他实例更新后，旧 revision 无法覆盖其草稿或队列。失败的编辑留在当前视图的 `unsavedDraft`，需要重试或另存本机副本。退出前由界面明确提示处理，因为这部分尚未落盘。重新打开可读取另一实例已经提交的本机记录。
