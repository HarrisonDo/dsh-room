## 0. 当前发布路线

2026-11-09 汇总今天的产品讨论与桌面插件调查。本节是下一轮执行入口，以下交付均为计划；实现状态只在 12 更新。保留 R01–R05 编号，将 R03 从独立安装包调整为 DSH 内的桌面能力，独立安装包移为 R06。

### 0.1 本轮承诺与后置范围

近期承诺是给自己的 AI 一个可互动、可布置的家。视频和 GitHub 项目页提供介绍与真实下载入口，在线试玩继续复用公网试玩站。用户可以只体验网页，也可以安装插件；使用桌面功能时，由插件准备运行环境并打开窗口，不要求用户再手动安装另一个 App。

长期保留一个从公园起步的公共世界：玩家提交固定场景版本，通过通道逐步连接，区域还可以通往受邀的私人房间或独立玩法。作品的文字页面记录作者、版本和访问状态。“论坛”是内容组织比喻，不重新建设普通发帖聊天社区。

本轮不提前开发无限地图、实时共同编辑、任意脚本、离线 AI 永久模拟、用户托管、交易、完整家具市场或跨设备私有记忆同步。只有小规模用户证明愿意使用和创作后，才推进公共区域连接。已实现的云同步核心保留，不因调整优先级而重写。

### 0.4 DSH 启动桌面窗口的技术边界

```text
DSH 插件宿主（本机数据、模型调用、运行时与进程管理）
  ├─ DSH 内嵌房间视图
  └─ 受限通信桥 → Electron 辅助进程 → 透明房间窗口
                                           └─ 完整编辑窗口
```

这是待实现的接入结构。继续使用现有 Electron 壳，不因其他插件使用 Neutralino 或 Python 而迁移框架。

- 用户首次启用“放到桌面”后准备运行时，固定版本、平台与架构，验证下载内容，进度可见且可取消/重试。缓存放在本插件管理的目录；不擅自复用或覆盖其他插件的运行时，不依赖易被宿主升级替换的目录。辅助进程启动时处理继承的 `ELECTRON_RUN_AS_NODE`，不误将图形进程当 Node 启动。
- 宿主负责生命周期和有限重试，插件关闭或卸载时结束自己启动的辅助进程。DSH 退出时保存并停止联动桌面窗，R06 独立模式另有生命周期。取消下载不删除其他应用资源。
- 桌面页面只加载随包本地资源。桥只提供明确的模型请求、能力查询、快照与窗口操作，校验消息类型、体积、来源和在途请求；不提供任意文件路径、命令执行或通用网络代理。模型凭据留在宿主，不复制到页面或公共服务。
- 首轮优先父子进程通道，启动时完成版本握手并限制请求、超时和退出行为。若平台要求改用本机网络通道，单列说明并限定回环地址、会话凭据及来源；不放宽现有鉴权来接通桌面。
- 运行位置在 DSH 宿主所在电脑。浏览器访问远程 DSH 不会让辅助窗口出现在访问者的 Windows 桌面；远程/无图形环境显示能力不可用并保留内嵌体验。
- 房间拖动与家具点击使用现有命中逻辑。避免把整个场景标成原生拖动区域导致家具无法点击；按小窗内容范围创建窗口，保留按钮和气泡的交互空间。

### 0.5 本机接续与云同步分开验收

同一 DSH profile 的内嵌房间和它启动的桌面辅助窗，必须接续同一个家，不以“以后云同步”跳过这一项。旧实现只镜像部分 localStorage；R03b 已把 IndexedDB 的家具包和草稿纳入完整快照，后续改动必须保留该范围。

首轮采用一个可编辑视图。切换时旧视图停止模拟和在途 AI 请求，将房间、角色选择、门连接及必要自定义素材保存为有版本的本地快照；宿主确认持久化后交接控制权，再由新视图读取。失败则旧视图保持可用或保留可恢复副本。禁止仅靠两端定时上传同名键，或者关闭窗口时才尝试保存。迟到的旧视图写入必须被拒绝。

首轮先在家中切换窗口，共享场次中提示先回家，避免扩大为跨窗口实时场次接管。桌面小窗与完整编辑窗沿用交替运行。迁移历史存档前保留副本，验证同 profile 完整内容可恢复。

Web、独立 App、其他电脑的账户云同步继续按 14/16 后置。公开角色身份、房间存档、私人记忆、模型在线状态分别展示。DSH 模型可用不等于其他宠物插件的身份和记忆已导入。

### 0.6 UI、注册、审核与反馈的最小范围

| 场景 | 本轮安排 |

| 本地创作 | 模板、布置、导出/导入不要求账户；AI 辅助使用可校验格式和预览，不开放任意脚本 |
| 注册与来访 | 复用已有 GitHub 登录；需要分享或进入联网场景时再登录并返回原目标；无需配置服务器或重复创建角色 |
| 发布与公开收录 | 发布固定版本与进入公共推荐分开；先给新用户有限发布额度，邀请访问按权限；维护者收录公共版本，修改后作为新版本检查 |
| 内容检查与处置 | 自动检查格式/大小/素材引用；公开版本人工预览图片、文字和基本通行；保留作者/版本/来源；场景级问题反馈、关闭入口和停止问题场次具备操作路径 |
| 反馈 | 产品问题入口和公开情绪分开；让用户提交版本、所在步骤、问题描述及自愿提供的截图，诊断不收集密钥或默认上传聊天/记忆 |

R04b 对外按新方向展示前，要在服务端限制公开自由文本，并同步更新人工和 AI 动作接口。八种情绪为喜悦、信任、恐惧、惊讶、悲伤、期待、愤怒和厌恶；现有四种 emote 与 say 仍是旧实现，需要兼容处理与回归。主人与自己的 AI 的私人聊天保留。邀请接受、拒绝、退出属于权限操作，不能从“信任”等情绪推断授权；其他协作表达先小范围验证。

场景及家具中的描述属于外部内容，不能给宿主 AI 新增系统或工具权限。摘要与署名用于完整性和追溯，不等同于内容安全。旧帖子举报不自动覆盖场景，也不将“几个账号举报就断开公共道路”直接作为新规则。早期公共推荐由维护者处理并记录耗时，后续按实际规模增加有范围的协助者。

### 0.7 发布验证与反馈决策

- 每轮只跑受影响的有效检查。候选包和桌面窗必须从实际交付物运行；最终入口集成后做一次适当的回归，不重复运行无关全套测试。
- R03 首先验证 Windows，再按拥有的环境验证 macOS；签名状态、运行时下载和未验证系统在发行说明中如实列出，不要求用户关闭系统保护。多屏不同缩放、恢复到可见屏幕、下载失败、重复打开和退出残留进程都要验收。
- R04 用不同身份和干净内容库验证素材、邀请、撤权、离场与经历。更改公开动作规则时验证原始请求无法绕过，不能只看页面按钮。
- R05 分开记录首次见到场景、首次模型互动、首次桌面显示、首次分享的操作数及耗时；下载/授权/网络耗时另列。当前没有完成新用户实测，不填写虚构目标达成值。
- 若用户无法独立安装，先修安装；能使用但没有回访意愿，先改陪伴/互动；创作有意愿但做不出来，先改模板；审核超出维护者时间，则减少公开投稿能力和额度。
- 服务器先支持受控试用。已有 16 条连接公网短测不代表长期容量；保持连接/上传/素材配额和恢复能力。2.5D 降低表现与制作成本，公共存储和分发仍消耗服务器资源；用户要求的月度流量收尾继续放最后。

### 0.8 后续演进的触发条件

在安装与本地陪伴稳定、出现真实创作者之后，先完善固定家具版本获取与来源，再尝试“公园连接一块玩家区域”。采用有限展示入口和稳定区域身份，避免过早扩张面积稀释相遇机会。连接版须补入口权限、往返、版本更新、区域撤下及回公园恢复；独立玩法沿用分场实例。

自主探索继续采用普通规则处理移动和生活动作，模型只在需要决策、回应或整理经历时调用。现有模型调用预算与控制权机制继续复用；公开事实、角色感想和作者反馈分别保存。跨设备同步、用户托管和更复杂玩法由真实需求决定，不作为本轮默认追加任务。

| 2.5D 展示和布置 | `dsh-room/web/roomkit/{renderer,iso,depth,nav,editor,scene}.js`；`World.apply()` | 等距投影、遮挡、寻路、交互位、编辑撤销、场景序列化 | 原样复用内核；联网写操作经过 RoomHost，不能直接信任客户端 `apply()` |
| 多房间的家 | `web/roomkit/home.js`；`Home`、`app.goRoom()` | 本地房间、楼层、传送门、角色跟随和存档 | 首版导出其中一个场景成为世界；整栋家联网后置，不改坏原存档 |

| 角色卡和外形 | `web/roomkit/{character,bodies}.js` | 原生及部分 Tavern 卡字段导入、内置身体和模型适配 | 稳定角色身份、公开资料与私人设定分离；消除物种写死；通用精灵图系统后置 |
| 模型聊天 | `web/roomkit/app.js` 的 `chat()`、`applyActs()`；`lib/chat.js` | `ext.chat` 扩展点、DSH 模型、人设与历史、离线台词 | 分离“生成意图”和“执行效果”；结构化观察；补独立本地模型网关；修正提示词默认所有人都是鲸鱼娘 |
| 本地行为 | `web/roomkit/{brain,agents}.js`；`Brain`、`Director` | 需求驱动生活、动作队列、演出 | 单人继续复用；共享场景不能让各端独立驱动同一只角色 |
| 联机聊天原型 | `web/roomkit/town.js`；`Town.enter()`、`_cast()`、`_onPost()` | 进入场景、成员显示、回帖和本机 AI 自动回复 | 当前 `_cast()` 为成员创建 `brain: 'auto'`，没有权威位置/机关状态；新建场次客户端，不把旧 Town 无限扩成所有系统 |

| 服务存储 | `scripts/town-store.mjs`；`openStore()` | SQLite、事务、帖子持久化、备份 | 新世界/版本/场次/事件表；显式迁移；分页和真实总数；现有在场信息仅在内存 |
| 剧情 | `web/roomkit/story.js`；`Stories` | 本地触发、分支、变量和演出 | 不直接作为多人规则执行器；首版新增一个小型权威活动预设，复用表现层 |
| 经历 | `web/roomkit/memory.js`；`Town._summarize()` | 本机人物印象、聊天摘要、召回、导入导出 | 事实与感想分离、完成凭证去重、断线补领、稳定身份、失败提示；不能只在正常离开时保存 |
| 部署 | `deploy/town/`、`scripts/town-backup.mjs` | Node + SQLite + Caddy + 备份文件 | 限额、慢连接处理、服务隔离、监测、真实容器/反代/恢复验收；配置文件不等于已承压 |

代码中 `app.command()` 的成功往往只代表进入本地队列，不代表动作已经完成；新协议不能直接把这个返回值变成共同活动的完成依据。

## 4. 可单独交付的开发任务

每个任务完成后更新 [12 的状态表](12-开发交接与进度.md)。涉及多个子项的任务可分成连续的小轮次，但只有验收通过才标记整个任务完成。

为控制单轮上下文，W04 建议分“纯状态规则 / 持久化与恢复”两轮；W07 分“适配器与 DSH / 本地网关 / 双端真实验证”三轮；W09 分“事实保存与去重 / 摘要召回与界面”两轮。每轮必须留下能运行或验证的结果，交接页记录完成到哪个子步骤。待环境验收不应阻断不依赖该环境的后续本地工作，但不能跳过最终验收。

### W00 固定首版契约和测试素材

- **前置：** 无。只需先读 09、11、12 及本计划的任务范围。
- **产出：** 给 11 的字段形状补齐可被后续测试使用的最小合法世界、两名成员、三个信标、一条完成事件和一条经历样例，放入 `tests/fixtures/`。记录格式版本，不重复制作一份竞争规格。
- **检查：** 阅读 `scene.js`、`packs.js`、`town-store.mjs`，确认新类型与旧类型不冲突；确定新存储如何共享数据库连接。发现必须改变的约定先同步 11。
- **完成标准：** 样例可解析，引用和活动对象对应；12 中记录模块拆分的最终文件名。此任务不标记多人游玩已实现，也不写空壳 API 来凑进度。

### W01a 修复请求异常和输入边界

- **入口：** `scripts/town.mjs` 的 `serve()`、`tests/town.test.mjs`；新增独立 HTTP 回归测试文件。
- **修改：** 完整捕获请求体读取、中断、超时和写响应失败；设置请求/头部/连接的有界处理；校验顶层 JSON 类型。应用层限流与代理可信地址配置分开，不能信任任意客户端自填的转发 IP。
- **验收：** 本机发送半截请求后断开，进程存活且后续正常请求成功；超大、无效和过慢请求被有界拒绝；错误日志不输出令牌或完整正文。
- **边界：** 之前的中断故障在本机 Node 23 环境复现过，修复须在部署使用的 Node 24 再验证；不把本机结果当成实际代理链已通过。

### W01b 修复配额、列表和场景输入

- **入口：** `town.mjs` 的 `character/create/join`、`town-store.mjs` 的 `threads()`、`tests/town*.test.mjs`。
- **修改：** 计数单独查询，列表分页且不解析全场景；异步审核结束后在事务中重新检查资格和配额；重复加入不广播无变化信息；服务器校验场景结构。创建和修改类接口按账号及可信连接来源限额，过期计数器清理。
- **验收：** 并发创建角色无法突破 3 个；帖子总量检查不再受列表 `LIMIT 200` 影响；非法 `objects` 类型拒绝；重复加入不放大广播。旧测试的简化场景夹具按真实有效格式修正，不能关闭新校验来保测试通过。

### W01c 限制订阅、处理慢连接和身份失效

- **入口：** `town.mjs` 的 `send/streamIdentity/serve`、`web/roomkit/town.js` 的 `connect/disconnect`。
- **修改：** 新增连接总量、每账号/来源限额；慢客户端缓冲有界；退出、过期和封禁释放订阅。旧小镇仍可匿名读取公开信息，但无效令牌不能静默获得已登录权限。缩小全站广播，列表使用轻量变更通知。
- **验收：** 一个不读取数据的客户端不会令进程内存持续无界增长；离线释放连接和 presence；同一场景重复重连不会累积定时器；待审内容不会发给其他账号。新邀请场次的票据和权限在 W05 实现。

### W02 本地世界与完整内容包

- **入口：** `scene.js` 的 `World.toJSON()`、`home.js`、`packs.js` 的 `validatePack/exportPack`、`catalog.js`、`workshop.js`。
- **新增：** `shared/world-format.js`；本地世界草稿存储与发布包构建；固定版本依赖清单和校验函数。
- **复用：** 场景布置、撤销、已有家具和角色导入，不重写渲染器。最初可提供简洁的保存/导出入口，完整菜单在 W10 整合。
- **验收：** A 新建一个含自定义透明贴图家具的世界，在没有该家具包的干净浏览器环境中导入，位置、贴图、交互位一致；缺失依赖、同名不同内容、错误版本、非法结构、超限图片可解释地失败；离开后自己的内容库不被覆盖。
- **边界：** 第一版每个世界一个场景，不把整个多楼层家改为在线存储；不接受任意脚本和远程素材抓取。

### W03 版本发布与兼容存储

- **前置：** W02。
- **入口：** `town-store.mjs`、`town.mjs`；新增 `world-store.mjs`、`world-service.mjs` 的世界部分。
- **修改：** 世界归账号所有；草稿保存、发布、读取、分页；不可变版本与摘要；独立发布体积/频次额度；版本化迁移和只读兼容旧帖子。内置默认素材的构建清单要能由服务端验证。
- **验收：** 重启不丢世界；作者发布第二版后第一版不变；非作者不能覆盖；未经许可的账号不能下载私密发布包；在临时复制的旧库上迁移并重新打开，旧帖子和账号仍可用；重复启动不重复迁移。
- **边界：** 不直接改写用户现有 `dsh-room/town.db`；迁移测试只用临时库。旧帖子先保留旧入口，手动“复制为世界”可以后置。

### W04 唯一判定端与有界事件流

- **前置：** W03。
- **入口：** `scene.js`、`nav.js` 中可复用的纯逻辑；新增 `shared/session-core.js`、世界存储的场次/事件/回执部分。
- **修改：** 创建/暂停/恢复/结束，版本固定；`move/interact/say/emote` 的规范化入口；权威快照、`seq/epoch`、请求去重、事件补发与快照回退。存储与发送分开，避免持有数据库事务等待模型或审核网络调用。
- **验收：** 两份客户端状态应用相同事件后得到一致的逻辑位置和物件状态；重复请求只提交一次；旧代次不能写；崩溃重启保留已提交结果；事件窗口满后仍可恢复且内存/数据库增长受控。
- **边界：** 不建立全世界永久 tick，不同步逐帧渲染；先通过核心测试，网络权限和客户端整合分别在 W05、W06。

### W05 邀请与角色控制权限

- **前置：** W04、W01c。
- **入口：** `town-auth.mjs`、`world-service.mjs`、世界权限相关存储；新场次 SSE 入口。
- **修改：** 有效期、次数、撤销和账号绑定的邀请；成员权限；一次性短期订阅票据；单角色控制租约与接管；离场/封禁/移除清理。只允许本场订阅，逐条控制快照、素材、补发和动作的权限。
- **验收：** 未被邀请者既进不去，也读不到场景、成员和事件；并发兑换不超次数，同账号重试不多扣；被请离后旧连接不能继续读取；多窗口只有持租约者能控制，接管后旧窗口失效；登出和过期停止写入及订阅。
- **边界：** 暂不做好友系统、跨站登录、自动 P2P 或权限继承树；邀请链接/邀请码足够完成首版串门。

### W06 客户端入场和共同状态

- **前置：** W05。
- **入口：** `app.js` 的 `chat/applyActs/_syncAgents/command/openScene`、`brain.js`、`town.js` 的进出场参考；新增 `world-session.js`。
- **修改：** 先完成权限与素材准备再切换场景；失败回滚；进入时保护本地家、取消本地自主行为；仅根据提交事件应用共享效果；断线提示、补发、租约状态和离场恢复。共享模式拦截 UI、剧情、插件命令等写入路径，避免绕过 RoomHost。
- **验收：** 两个独立浏览器身份入场后状态一致；失败入场不把本地家卡在访客模式；断线/刷新后恢复进度；别人不会在不同客户端自主走到不同机关；离开后原家和原角色仍完整；拒绝动作不先在画面产生永久效果。
- **边界：** 只读远端角色仍可播放纯装饰动画；不能靠设置 `brain: manual` 却继续让状态联动或导演修改共享物件。

### W07 各自携带 AI

- **前置：** W06。
- **入口：** `lib/chat.js`、`app.js`、`src/{client,web}.js`、`scripts/{preview,launch}.mjs`；新增主人侧适配器和本地网关。
- **修改：** 稳定本机角色身份映射；中性角色提示词；观察包含物件实例 id、可执行动作和结果；模型只返回意图；接入 DSH 与独立本地网关；每次调用预算、超时、取消和手动降级。
- **验收：** A 使用 DSH，B 使用独立预览和自己的模型连接，两者的人设和记忆隔离；其中一端密钥失效不会影响另一端或破坏活动；离场后迟到结果不再提交；世界导出和平台请求里没有私人设定、密钥或完整私有记忆。自动化用确定性适配器，真实调用另有手动验收记录。
- **边界：** 网关只在用户本机运行，不在平台加一个万能模型代理；先支持一个明确的模型请求格式，具体外部 API 字段以实施时的官方文档为准，不在此预先承诺兼容所有服务商。

### W08 合作活动与完成凭证

- **前置：** W06；与真实 AI 结合的验收还依赖 W07。
- **入口：** `shared/activities.js`、`session-core.js`、`story.js` 的表现能力、世界服务及存储。
- **修改：** 合作信标预设、目标 UI 数据、交互条件、贡献账号去重、完成资格和唯一凭证；规则在 RoomHost，演出在客户端。活动模板可以绑定作者摆放的物件实例。
- **验收：** 同抢一个信标只有一次效果；一个账号换角色不能伪造两人合作；两人完成后所有客户端的结果相同；重复点击/重发不重复完成；晚加入者不冒领；两组人玩同一版本的不同场次，进度互不影响。
- **边界：** 不开发战斗、交易和数值经济，不执行任意剧情脚本，不把“AI 说自己完成了”当成事实。

### W09 经历保存、补领和召回

- **前置：** W08、W07 的摘要接口。
- **入口：** `memory.js`、`Town._summarize()`、新 `experience.js`、角色 UI；完成凭证读取接口。
- **修改：** 关键事件即保存、完成凭证去重、本地事实与感想分离、断线重连补领；稳定角色与服务来源；旧记忆兼容；查看/删除/导出导入；存储失败提示。
- **验收：** 完成后立即断开或刷新仍有经历；摘要超时也保留事实；重复补发不重复计数和调用模型；两只角色记忆不串；下次同伴相遇可召回本次事实；用户删除后重连不会擅自恢复；旧版记忆导入后仍可查看。
- **边界：** 保持本机存储，不上传私有记忆；不把首次记忆闭环称为完整的长期人格养成。

### W10 整理完整用户流程

- **前置：** W02–W09。
- **入口：** `shell.js`、`style.js`、`app.js`、世界/适配器/经历模块；若 shell 继续变大，将新世界面板单独拆出。
- **修改：** 我的世界 → 保存/发布 → 开场/邀请 → 选择角色和模型状态 → 活动面板 → 完成记录 → 回家；支持粘贴邀请码；展示暂停、断线、失败和恢复。旧小镇保留独立入口。
- **验收：** 作者和访客不使用控制台即可完成全流程；界面不显示数据库名、协议字段等实现细节；普通宽屏和窄窗口可用；离场、拒绝邀请、缺素材、无模型均有明确可恢复路径。
- **边界：** 不重做所有布局，不添加首版流程用不到的社区页面。公共网页未连接本机模型时明确说明玩法入口。

### W11 整体验收与小范围部署

- **前置：** W10；对外发布还要完成 L1 中与实际分发有关的检查。
- **修改：** 补完整闭环回归和部署说明；合理的进程资源额度、连接/消息/流量指标、日志脱敏、限额提示、备份恢复。接入防护与现有同 IP 服务的端口暴露分别核查，不能用前置代理掩盖其他公开入口。
- **验收：** 按下一节逐项记录；Node 24、实际容器和反向代理下测试断线重连与恢复；逐级增加受控房间和连接，记录 CPU、内存、延迟、错误率、出站字节和剩余流量预算，给出保守的初始开放额度。未跑的项目标明待环境验收。
- **边界：** 不用用户现有服务做破坏性负载实验。先准备可审阅的配置和本地测试，具体部署按届时已有授权执行。对外介绍只展示验收过的功能。

### L1 引擎独立运行与许可整理

- **范围：** 根 `LICENSE`、README、包元信息、`scripts/build.mjs`、`web/index.html`、`src/client.js`、`web/vendor-src/`、`room/vendor/coopanion/`、默认角色/素材、关于页面。
- **先做：** 来源和授权清单；核查历史版本、第三方及贡献权利、实际打包内容、源码与署名提供方式；区分现有许可、未来许可意图和仍未确定的素材授权。
- **技术产出：** 可单独构建和运行的通用引擎/中性示例入口，默认不必须加载特定形象和模型。外形、人设、模型服务与联机服务各自有适配边界。
- **验收：** 不带特定模型和素材，仍能运行首版闭环；发布包包含应有的许可证/说明；README、关于页面与实际分发一致。最终许可证或服务端闭源边界必须有权利依据，不能直接把现有 AGPL 改成 MIT/MPL。
- **边界：** 此任务不是“先选一个开源协议再继续开发”；不因审计未完成而阻止本地功能开发，但相关公开发布不能借新方向跳过许可问题。

### W12 公共目录、家具分发与共同改进

- **前置：** W10 和已有公网验证；目录入场依赖 UI02 的认证与稳定角色，扩大开放前完成对应发布检查。W11 月度流量收尾不作为本地开发前置。
- **目录子任务：** 按 UI03 实现公开/不列出/受邀可见性、世界卡片、真实公共入场与容量处理。公共广场同样使用场次协议、人数上限和无人暂停。无邀请用户可进入已开放世界，私人世界仍按邀请授权。
- **家具子任务：** 按 UI04 实现所选家具及必要依赖的发布、作者账户绑定、固定版本和摘要、改编来源、审核/下架、获取与本地收藏。公共家具库负责分发，公共世界负责展示和交流；普通下载权限不等于布置公共世界权限。首轮发布/维护角色分开，不能把审核与入场绑定成每个玩家都要人工批准。
- **后续协作：** 作品与讨论帖关联、主题活动、作者更新说明、复制或提交改进版本；作者确认发布，运行场次固定版本。
- **验收：** A 分享家具，B 获取对应版本、查看来源并放进自己的家；只导入允许的家具数据及资源，拒绝脚本/非预期字段/摘要不符。A、B 可从目录进入 D 的作品，D 发布更新不改变旧场；私人场次与记忆不出现在公开搜索/帖子；被下架内容停止新分发和新场展示。
- **边界：** 不做一整个常驻大世界，不要求社区所有物品永久模拟，不允许他人直接覆盖作者已发布版本。摘要不能证明内容无害或作者拥有原创权利；来源、格式和 AI 输入隔离分别处理。完整三端同步不是家具发布/获取的前置。

### W13 用户托管的小世界

- **前置：** W11，且共享核心已能脱离平台 HTTP/数据库运行。
- **顺序：** 先让用户在自己的常在线节点运行同一 RoomHost 并接入目录；再试房主本机运行，通过认证的出站连接与平台中继相连；确有需求再研究直接连接。
- **验收：** 客户端和世界内容不因 Host 变化而改写；跨两个不同网络的受邀玩家可进入；房主掉线暂停，恢复不分叉；私有模型和记忆不移交给 Host；记录平台中继带宽与节点带宽的变化。
- **信任边界：** 自托管者可以修改自己的世界规则和本节点状态，平台不能把其完成记录当成全站可信资产或奖励依据；经历显示来源。不默认请求任何电脑执行世界上传的代码。
- **边界：** 首轮不做自动选主、跨节点无缝迁移、联邦账号、全球排行榜；中继仍走平台时只分担计算，并不代表平台带宽已经省掉。

## 5. 首版闭环验收清单

| 编号 | 必须观察到的结果 | 建议验证方式 |
|---|---|---|
| E01 | D 新建含一个自定义家具的世界并发布；重启后可重新打开 | 世界/包测试 + 浏览器 |
| E02 | 两个不同账号领取邀请；第三个未获邀请的账号无法读取和加入 | API 与实际 HTTP/SSE 测试 |
| E03 | A、B 分别选自己的角色；DSH 与独立网关均能接真实模型 | 两个独立配置环境手动验收；不能只开同源共享登录的两个标签 |
| E04 | 访客首次进入即可看到自定义家具、同样的活动对象和进度 | 干净浏览器存储 + 界面验收 |
| E05 | 两人共同完成信标活动，重复/并发操作不重复产生效果 | 确定性核心测试 + 双客户端 |
| E06 | 两个队伍开同一世界版本，状态互不污染 | 两场次集成测试 |
| E07 | 掉线、刷新、慢连接与服务重启后恢复一致；撤权立即生效 | 故障注入，仅本地/测试环境 |
| E08 | 模型超时或无额度仍能手动完成，密钥/人设/私有记忆没有上传 | 失败适配器 + 请求载荷检查 |
| E09 | 完成即关页，重进后经历仍存在；摘要失败不丢事实、不重复花费 | 存储与恢复测试 |
| E10 | 回家保留原房间，下次相遇召回共同活动；删除经历后不再召回 | 浏览器 + 召回输入断言 |
| E11 | 无人场次暂停，模型调用停止；负载停止后资源回落 | 定时器/取消测试 + 指标记录 |

M3 的完成需要 E01–E12 对应功能通过；与真实模型、真机宿主相关的未验证部分必须单列。自动化测试通过不等于 M4 公网发布条件满足。

## 6. 测试和成本安排

- 现有 `dsh-room/tests/` 使用 Node 内置测试，优先延续。纯规则测试不依赖模型服务、真实登录或外网；权限和请求中断必须补实际 HTTP/SSE 测试，不能只直接调用内部函数。
- 每个任务先跑对应测试；阶段结束跑 `npm test`。改浏览器源码或入口时运行 `npm run build` 并检查生成产物；只改文档不运行构建来制造无关变更。
- 涉及界面的阶段做必要的双身份浏览器验证。无法使用某种真实宿主、Docker 或模型配置时，记录限制和可复现步骤，不伪造“已通过”。
- 6.1 sol 按任务领取、按失败用例验收。不要一次性让模型读取所有历史文档、素材、构建产物或大数据库，也不要在每轮重新调研竞品和框架。
- 不给整项开发承诺固定 token 数或日历天数。W04–W09 的状态、权限和失败恢复最容易返工，应保留独立检查点；文档和测试的价值是减少重复理解和错误重写。
