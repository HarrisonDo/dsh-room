# 02 · 房间诊断与 2.5D 升级（s2.0）

> 2026-11-04。对照 [jolly-small-plays](https://idonafraid-create.github.io/jolly-small-plays)（下称 JS P）排查"房间只是几个可交互 box"的根因，给出修复与规范化方案。
> 结论先行：**内核架构没问题（等距网格 / 深度三明治 / 时段天气 / 布置模式都在），坏在"素材没接线 + 命中区错位 + 三个拦截点击的坑"。修完后房间已经是 2.5D 动漫风实体房间，且不需要 WebGL / 体素 / 建模。**

---

## 一、为什么之前是"几个可以交互的 box"

按杀伤力排序（每条都已修复并实测）：

| # | 问题 | 位置 | 现象 |
|---|------|------|------|
| 1 | 壳图路径写 `.png`，磁盘上是 `.jpg` | `packs/default/pack.js` shells | 壳图 404 → 房间没有墙和地板，只剩暗底 + 阴影 |
| 2 | 8 个家具定义**全都没有 `sprite` 字段** | `packs/default/pack.js` furniture[] | 全部走 `placeholderSprite()` → 带名字的等距蓝方块（用户看到的"box"） |
| 3 | 命中区写成**绝对 viewBox 坐标**，但多边形在已 `translate(inst.x, inst.y)` 的 group 里 | `core/room-core.js` `updateHitGeom` | 命中菱形整体偏移出场景 → 真实鼠标点不到；`dispatchEvent` 逐元素派发却能过（正好是 README 里"合成事件假阳性"的坑） |
| 4 | `svg-back / svg-front` 根元素拦下整块区域的事件 | `core/room-core.css` | 后排家具、窗户、门全部点不到（只留 `.fz` 可点时反而需要根上 `pointer-events:none`） |
| 5 | `whale-resident` 在 figure 异步加载完成后才注册 `room:ready`，而事件早发过了 | `plugins/whale-resident.js` | `sceneReady` 永远 false → 大肥鱼不走位、不落座 |
| 6 | 素材缺陷：desk 桌面被抠穿、plant-wardrobe 一图两物、lamp 内容偏在画布右侧、没有窗贴图、壳图带 AI 水印 | `packs/default/furniture/*.png` | 就算接线也是破图 |

另外两个隐性坑：
- **壳图参照尺寸陷阱**：壳图实际是 2496×1564，图片查看工具显示的是缩略 2000×1253。按 0.768 换算窗户坐标全部错位 → 雨雪粒子落到门框上。
- `switchScene` 同场景不重载（按设计），调试时容易误以为"布局没还原"。

### 修复清单（本轮）

1. `pack.js`：壳图改 `.jpg`；7 件家具全部接上 `sprite` + 按贴图纵横比校准 `spriteSize`；`window` 家具改为 hitZone（见下）。
2. `room-core.js`：`updateHitGeom` 改为**相对 group 原点**；新增 **hitZone**（锚在壳图画面上的矩形命中区，支持 `window` 天气裁剪、`act:'weather'`）；新增**相机**（滚轮缩放 1–2.6×、空白处拖拽平移、双击复位）；新增壳图 `error` 兜底（画程序化壳）；HUD（名牌/浮字/气泡）改用 `getScreenCTM` 反算，随相机正确跟随；切场景自动关抽屉。
3. `room-core.css`：`svg` 根 `pointer-events:none` + `.fz { pointer-events:auto }`；`.room-camera` 相机层样式。
4. `whale-resident.js`：模型就绪即 `sceneReady=true` 并补一次开场作息；切场景后重新走位到新场景书桌/床；坐标换算改用 `clientWidth/Height`（相机变换不影响布局像素）；支持 `{anchor:'bed'}` 形式。
5. 素材：新建 `tools/room-furnish.py` —— raw 重抠（局部背景估计泛洪）/ Seedream 品红幕布确定性抠图（近色家具专用）/ trim / 一图两物拆分 / 壳图去水印，一条命令重建全部贴图。
6. `pack.js` hitZone 坐标按**真实像素**（×1536/2496、×1024/1564）重新换算：卧室窗 `[754,190,201,271]`、卧室门 `[1033,360,123,259]`、书房拱窗 `[652,164,138,337]`、书房空画框 `[822,265,157,252]`。

## 二、对照 jolly-small-plays：它到底是怎么做的

从它的 HANDOFF 与线上页可核实：

- **介质**：three.js（WebGL），2:1 等距，`Low-res pass ×4` = 低分辨率渲染再放大（像素颗粒感的来源）。
- **美术管线**：AI 逐件出图（codex，**直接透明背景**）→ 脚本裁切/拆分成 `obj/*.webp` + 一份 `objects.json` 摆放表 → 代码里按等距锚点摆放。
- **场景 = 分层贴图 + 画家算法**：底 + 道具层 + 角色层 + 相机（滚轮缩放 / 拖拽平移 / hover 名牌）+ 声音 + 深浅主题。
- **它没有**：3D 建模、体素、实时 3D 光照。立体感全部来自等距插画本身 + 分层 + 统一朝向的投影。

也就是说，**它和我们的路线是同一套骨架**，差别只在：它用 WebGL 跑"像素低清渲染"，我们用 SVG 跑"高清动漫贴图"。要做出用户要的效果（2.5D 动漫、非体素），不需要 WebGL：

| 效果要素 | JS P 的做法 | 本项目的对应 | 状态 |
|---|---|---|---|
| 等距场景 | three.js 正交相机 | viewBox 等距网格（cellW/cellH/origin 按壳图实测校准） | ✅ s1 |
| 立体感 | 等距贴图 + 分层 | 贴图 + 深度三明治（后排家具 ← 角色 ← 前排家具） | ✅ s1/s2 |
| 物件即按钮 | hover 名牌 + 点击 | `.fz` 命中菱形 + 浮字 + 抽屉 | ✅ s2 修好 |
| 相机 | 滚轮缩放/拖拽 | `.room-camera` CSS transform（缩放锚光标、平移钳制、双击复位） | ✅ s2 |
| 窗外天气 | 粒子层 | 粒子裁剪在窗玻璃矩形（hitZone.window） | ✅ s2 对齐 |
| 日夜/光照 | 主题 + 后期 | 四时段插值 + `--brightness/--ambient` 滤镜 + 灯/屏幕光 | ✅ s1 |
| 声音 | 配乐/音效 | 未做（可选 s2.2） | ⏳ |
| 低清像素 pass | `×4` 降采样 | 动漫风不需要；SVG 矢量天然任意倍清晰 | — |

**什么时候才值得上 three.js**：真 3D 旋转相机、动态实时阴影/光照、海量粒子、视频贴图。当前 1536×1024 单场景在 SVG+CSS 下性能足够，且 DSH 插件分发零依赖、可静态部署——保持现状更划算。

## 三、房间与设施的规范化（后期自定义契约）

> 目标：以后换房间/加设施 = 换数据，不改内核。

### 3.1 room-pack 结构

```js
{
  type: 'room-pack', id, name,
  viewBox: [1536, 1024],
  iso: { cellW, cellH, origin: [x, y], grid: [6, 6] },   // 按壳图地板菱形实测
  shells: { 场景key: 'packs/default/shells/xxx.jpg' },
  furniture: [ FurnDef... ],                              // 家具库（可跨场景复用）
  scenes: [{
    id, name, shell,
    iso?,                                                 // 可选：每场景覆盖网格
    furniture: [{ instId, defId, gx, gy }],               // 摆位（格坐标）
    hitZones: [{ id, label, sub, rect:[x,y,w,h], window?, act? }]  // 锚在画面上的命中区
  }]
}
```

### 3.2 FurnDef（家具定义）

| 字段 | 说明 |
|---|---|
| `id / name / sub` | 身份与悬停名牌文案 |
| `foot: [w,h]` | 等距占地（格），决定命中菱形与深度 |
| `sprite` | 透明贴图路径（缺失/加载失败 → 占位方块兜底） |
| `spriteSize: [w,h]` | 显示尺寸；宽按 foot 跨度定，**高必须按贴图纵横比** |
| `flat: true` | 地毯类：永远在角色身后、中心锚 |
| `anchor: {pose,dx,dy}` | 大肥鱼落位（pose: sleep/work/stand） |
| `states / mount / on.act / on.change` | 状态机、自绘活动件（灯光/屏幕光）、点击反馈 |
| `hitOnly` | 内部用：只做命中区不渲染 |

### 3.3 壳图与网格校准（换房间必做）

1. 壳图按 **3:2** 构图（推荐 2496×1564，水印去干净），地板画成等距菱形，墙面留白放窗/门。
2. 量出地板菱形四顶点 → `cellW = 菱形宽 / grid[0]`，`cellH = 菱形高 / grid[1]`，`origin = 菱形上顶点`。
3. 窗/门位置用**真实像素**读（不要用图片查看器的缩略尺寸），按 `×1536/图宽、×1024/图高` 换成 hitZone rect。
4. 校准验证：`?calib=1` 进布置模式，拖家具对齐；命中区悬停看名牌 + `elementFromPoint` 实测（**不要用 dispatchEvent 验收**）。

### 3.4 素材流水线（新家具三步接入）

```bash
# ① 下载/生成 1024+ 透明感素材，放 packs/default/furniture/raw/<名字>.jpg
# ② 一件一拍：Seedream 把背景换成纯品红幕布（近色家具也安全）
#    提示词要点：背景 #FF00FF、家具保持原样、不要投影/地面/阴影、居中
# ③ 一条命令重建全部贴图（品红抠图 / trim / 一图两物拆分 / 尺寸表）
python3 tools/room-furnish.py
```

- 输出：`furniture/<名字>.png` + `sizes.json`（最终像素尺寸，填 `spriteSize` 时按纵横比换算）。
- 纯色/白底素材也可以直接走 raw 局部背景估计泛洪；**奶白/浅色家具在浅底上必须走品红幕布**，否则会被当背景抠掉。
- 窗/门**不用贴图**：壳图里画好，pack 里写 hitZone（省一张图，还能让天气粒子精确裁剪）。

### 3.5 布置模式（已可用）

导演模式「标注模式」= 布置模式：拖家具吸附格点 → 退出自动存 `localStorage['room.layout.<pack>.<scene>']` → 「恢复默认」清除。后续可加"导出布局 JSON"给多机器复用。

## 六、s2.1 追加（家具库 / 多房间包 / 常驻模式 / 音效）

### 6.1 家具库（布置模式）

- 进入布置模式后右侧出现**家具库面板**（缩略图 + 名称，来自 `pack.furniture`，含 `extends` 继承的条目）。
- 点击条目 → `room.addFurniture(defId)` 自动找最近空位放下；房间满时落在角落，可手动拖开。
- 每件占格家具右上角有红色 **×**（仅布置模式显示）→ `room.removeFurniture(instId)`。
- **布局存档 v2**：`{ v:2, items:{instId:{gx,gy}}, added:[{instId,defId,gx,gy}], removed:[instId] }`（v1 旧存档自动兼容），布置模式退出/增删时自动保存，`恢复默认` 清档重载。
- API：`room.addFurniture(defId, gx?, gy?)` / `room.removeFurniture(instId)` / `room.saveLayout()`。

### 6.2 多房间包 + 家具库继承

- 房间包新增 `extends:'default'`：家具库从基础包继承，同名覆盖，新包只写壳/摆位/hitZone。
- 示例 `packs/living/pack.js`：客厅壳（2496×1664）、**8×6 网格**（比卧室 6×6 更大的布局）、6 件家具、窗/门 hitZone；`room.setPack('living')` 切换，导演条出现包按钮。
- 多包约束：所有包共用同一 `viewBox`（1536×1024）；每包/每场景自带 `iso`。
- 新包接入步骤：① 壳图放 `packs/<id>/shells/` → ② 量地板菱形得 `cellW/cellH/origin/grid`（可用页面里临时画网格叠加层校准，见本次做法）→ ③ 写 `pack.js`（壳 + 摆位 + hitZones）→ ④ `index.html` 加一行 `<script>`。

### 6.3 尺寸与挂载（web / 桌面右下角 / DSH）

- 页模式舞台最大 **1100px**（原来锁在 920px），随视口自适应；房间内部布局不再受开发阶段小尺寸限制。
- `?dock=1`：右下角常驻卡片，`w` 参数或页内 **S/M/L（420/620/860）** 切换，`收起` 成右下角小胶囊（🐋 大肥鱼的房间），尺寸与收起状态存 localStorage。
- DSH 右侧栏（320–420px）直接嵌入可用；窄屏下家具库面板占宽约 160px，仍可操作。
- 嵌网页建议 iframe 贴右下角（`position:fixed; right:16px; bottom:16px; width:620px; height:auto; border:0`）。

### 6.4 轻音效（可选）

- WebAudio 合成（无音频素材）：点击家具一声短促「嗒」，默认**关**；导演条「声音」开关，状态存 `localStorage['room.sound']`，首次交互解锁浏览器音频限制。

### 6.5 本轮实测

- 家具库：添加（真实点击条目）→ 新实例落位 ✓；删除（真实点击红色角标，`elementFromPoint` 命中 `text`）✓；`removed/added` 存档 ✓；重载/切场景后仍生效 ✓；恢复默认还原 ✓。
- 多包：`room.packs()` 两项，`setPack('living')` 后壳/网格/家具/hitZone 全换、家具库继承 7 项 ✓；客厅窗/门矩形与画面叠加校验对齐 ✓；大肥鱼在新场景重新走到书桌 ✓。
- 右下角模式：`?dock=1&w=620` 贴右下角、S/M/L 切换与收起 ✓；视口 440px 时自动钳制宽度 ✓。
- 音效：开关切换、点击路径无异常 ✓（真机听感待用户确认）。
