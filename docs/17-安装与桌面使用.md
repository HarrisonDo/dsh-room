# 安装与桌面使用

## 第一次使用

先打开 [网页试玩](https://dshroom.pigeongugu.store/) 看小屋效果，不需要安装。试玩满意后，在 DSH 的「插件」页点击「添加插件」，粘贴：

```text
https://github.com/HarrisonDo/dsh-room
```

点击「安装」，完成后点「立即启用」，打开「大肥鱼的房间」。这不是 npm 包名，不需要填写版本、子目录或下载文件路径。不要选仓库中的 `dsh-room/` 子目录作为普通安装入口；它是开发源码。

首次看到小屋和 Q 版鲸鱼娘后，可以点击地面行走、点家具互动，左键房门直接换房，右键房门打开交互菜单。聊天使用 DSH 当前选好的模型。没有模型也能体验房间；配置模型沿用 DSH 自己的设置。

## 放到桌面

在房间中点击「放到桌面」。首次会下载并校验运行组件，显示下载进度，可取消再重试。不要因为暂时没有弹出窗口而重复安装插件。准备完成后房间会出现在透明桌面窗中。

桌面可以拖动、调整大小，并通过右键菜单打开完整房间或回到 DSH。完整房间适合布置和聊天，透明小窗适合留在桌面。切换会带上同一套房间、角色、家具包和世界草稿；原窗口暂停，避免两个窗口同时写入存档。

DSH 提供存档与模型连接，需要保持运行。退出 DSH 后辅助窗也会结束。重新打开后可再次接续。插件不会把 DSH 的模型密钥复制到桌面页面，也不要求另配一套 API。

当前 Windows 桌面实现仍待实机验收；不要把 macOS 结果当成 Windows 已通过。独立 Electron 安装包属于后续发布渠道。

## 安装失败、更新与反馈

- **GitHub 连接失败或提示找不到 Git**：DSH 的仓库安装入口会调用系统 Git；没有 Git 时不必为了试玩先配置开发环境。可在 [备用下载页](https://dshroom.pigeongugu.store/assets/dsh-install.html) 复制固定版本的插件下载地址，仍粘贴到同一个「添加插件」框安装。
- **已安装旧版**：先备份自己的场景。依 DSH 的插件管理提示卸载旧插件再安装仓库地址，避免重复安装两份。不要手动删除本地存档目录。
- **桌面下载失败**：房间仍可在 DSH 中使用；恢复网络后点击重试。组件校验不通过时不会启动。
- **找不到桌面窗**：检查 DSH 是否仍在运行、房间入口是否显示下载或错误状态。重新进入房间后重试；不要自行删存档。
- **网页布置没有出现在 DSH**：网页试玩和 DSH 本地存档独立。此版本的“接续”指同一 DSH 与它启动的桌面窗，不是跨设备云同步。

反馈到 [GitHub Issues](https://github.com/HarrisonDo/dsh-room/issues)，附操作系统、DSH 版本、插件版本、从哪一步开始失败，以及不含隐私的截图。不要贴模型密钥、登录令牌、完整聊天记录或私人存档。

## 参与共建

源码在 `dsh-room/` 和 `desktop/`；仓库根 `install/` 是可直接安装的发布快照，不要直接改它。用 Node.js 24 在 `dsh-room/` 执行 `npm ci`、`npm run build` 和 `npm test`。开发时从本地源码目录加载，发布前生成新候选并验收。

候选的 `SHA256SUMS` 同时覆盖插件包和同版本源码。维护者运行：

```sh
node scripts/stage-github-install.mjs /绝对路径/候选目录
npm run test:install
```

这会将候选逐文件校验后放进 `install/`，生成根 `package.json` 和 `release.json`。根包没有安装时构建脚本，不依赖用户的开发工具。更新候选不能覆盖已公开版本号；对应源码及校验值须同时公开。整仓源码构建可包含可选演示资源，安装包所含内容以该候选的 NOTICE 为准。
