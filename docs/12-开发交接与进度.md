## 4. 每轮工作规则

1. 检查实际代码和工作区变更；上一轮记录是入口，不能盲目信任已经变化的接口。
2. 说清当前任务范围。读取指定入口和对应测试，不把所有历史讨论重新塞入上下文。
3. 对照 11 实现最小可用结果。通用规则应复用；不要为让测试通过新增与正式路径无关的第二套模拟实现。
4. 只新增能验证风险与行为的测试。覆盖权限、状态一致性、重复提交、恢复和数据迁移；不写机械复刻实现的测试。
5. 完成相关检查后更新任务状态及下一节。没有新变更或失败原因，不反复跑相同全量检查。
6. 汇报实际结果；需要真实环境的步骤写具体，不把所有工作都笼统交回用户。

若获得多 agent 并行开发指令，先按模块指定文件责任范围。`app.js`、`shell.js`、`town.mjs`、`town-store.mjs`、构建入口和本交接页均由一个负责者修改；主 agent 汇总、去重、裁决冲突后合并。没有明确并行安排时顺序开发，避免共享文件冲突。

W03 在 `town-store.mjs` 的 `openStore()` 初始化旧表后，将同一连接 `db`、语句缓存 `q` 和同步事务入口 `tx` 传给 `createWorldStore()`，通过 `store.world` 交给服务层。`openStore()` 负责连接、备份与关闭。新迁移在事务内写入 `world_schema_migrations`，场次用 `world_sessions` 区分登录会话。命令回执、事件、快照和完成凭证由服务层使用同一个同步事务写入，提交后再广播。

### 7.4 1Panel Docker 与 Tunnel 实测

2026-11-07 使用 ARM64 服务器，Node 24.22.2 与 Caddy 2.11.4。独立 Compose 项目 `roomkit-w11` 在 `/opt/roomkit-w11-20261107`。Cloudflare 处理公网 HTTPS，现有 Tunnel 将请求交给 `127.0.0.1:18610` 上的 Caddy。小镇容器的 `18780` 没有主机监听，`muse2api` 检查时处于停止状态。 [公网健康检查](https://mu2a.penguingugu.com/health)

- HTTPS `/health` 返回 `200 ok`。公开服务关闭原型登录。临时账号验证未登录请求和未受邀账号被拒绝，普通账号不能读取管理指标。
- 旧小镇 `/events` 与世界 `/world-events` 首帧分别为 481 ms 和 348 ms。访客断开后服务端订阅从 2 降到 1，重连补到了漏掉的移动。两端完成合作并领取凭证，撤权即时结束订阅。
- 在线备份为 212,992 B。复制到独立容器后读回发布版本、场次状态和完成凭证，备份中包含离场及暂停事件。重启小镇容器后，公网接口返回相同进度和凭证，场次代次递增并可恢复。
- 公网短测 4 场、8 条订阅、16 个移动动作，失败 0，客户端请求 p95 为 839 ms，动作阶段应用层出站为 11,061 B。结束后活跃订阅归零。`docker stats` 采样中小镇最高 2.24% CPU、21.44 MiB，Caddy 最高 1.97% CPU、14.86 MiB。空闲采样分别为 0.01% CPU、21.44 MiB 和 0.00% CPU、14.82 MiB。
- 慢连接短测让访客停读约 3 秒后主动断开。重连从序号 `2` 补回 `actor.moved` 和 `beacon.lit`，追到 `4`。访客归约后的信标进度 `1 / 3` 与服务器快照一致。
- 公网短测 8 场、16 条订阅、32 个移动动作，失败 0，客户端请求 p95 为 608 ms。动作回执 7,980 B，移动 SSE 13,016 B，合计 20,996 B，按客户端收到的应用层内容计。各场次两端分别收齐本场的 4 个动作，结束后 16 条测试订阅均收到退出通知并关闭。
- 8 场测试窗口的 `docker stats` 采样中，小镇峰值 7.98% CPU、22.14 MiB，Caddy 峰值 2.73% CPU、16.39 MiB。扩容前空闲采样为小镇 0.01% CPU、25.56 MiB，Caddy 0.00% CPU、12.65 MiB。恢复默认 4 场、16 条订阅后，`18610` 仍只在回环监听，`18780` 未映射，其他 TCP 监听地址与本轮短测前一致。

测试实例保留运行，短测的临时会话已撤销。端口对照使用本轮短测前的同机监听快照。流量数值来自短时样例场景，服务商月度剩余流量排在最后。采用 Caddy 直接终止 HTTPS 的部署还需验证证书签发。

### 7.6 L1 打包与中性示例

#### 中性候选复测

本次 `roomkit-neutral@0.1.0-l1.0` 的实际交付目录如下，包含 npm 包、同版本源码、`SHA256SUMS` 与 `SOURCE-INPUTS.sha256`。 [构建与下载说明](../dsh-room/neutral/README.md)

```text
/本机验收归档/roomkit-neutral-l1
```

如需从当前工作区重新制作候选，在源码仓库的 `dsh-room/` 用 Node.js 24 执行。目标目录需为新目录。

```sh
node scripts/pack-neutral.mjs /绝对路径/新的交付目录
```

在 `dsh-room/` 用以下命令复测本次交付。源码重建在独立临时目录运行，浏览器冒烟读取解包后的 npm 客户端，临时小镇服务端由工作区的测试夹具提供。

```sh
delivery='/本机验收归档/roomkit-neutral-l1'
check_dir="$(mktemp -d)"
candidate=roomkit-neutral-0.1.0-l1.0
(cd "$delivery" && shasum -a 256 -c SHA256SUMS)
tar -xzf "$delivery/$candidate-source.tar.gz" -C "$check_dir"
tar -xzf "$delivery/$candidate.tgz" -C "$check_dir"
(cd "$check_dir/source" && shasum -a 256 -c SOURCE-INPUTS.sha256 && npm ci && npm pack --pack-destination "$check_dir")
cmp "$delivery/$candidate.tgz" "$check_dir/$candidate.tgz"
node tests/browser-world-smoke.mjs --example --package-root="$check_dir/package"
```

本次两个归档的校验值通过，重建归档逐字节一致，解包客户端的双身份合作冒烟通过。公开下载地址待发布。

手动复测时在中性 npm 包的解包目录用 `npm run serve` 打开 `http://127.0.0.1:18766/`。在「社区 → AI 世界」勾选合作信标活动，分别选格 `(1, 1)`、`(3, 1)`、`(5, 1)` 的三盏信标和格 `(5, 4)` 的出口，再保存草稿。按第 7.2 节用两个账号发布、邀请和点灯。回家后可在「我的经历」查看完成记录。
