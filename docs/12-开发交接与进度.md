## 4. 每轮工作规则

1. 检查实际代码和工作区变更；上一轮记录是入口，不能盲目信任已经变化的接口。
2. 说清当前任务范围。读取指定入口和对应测试，不把所有历史讨论重新塞入上下文。
3. 对照 11 实现最小可用结果。通用规则应复用；不要为让测试通过新增与正式路径无关的第二套模拟实现。
4. 只新增能验证风险与行为的测试。覆盖权限、状态一致性、重复提交、恢复和数据迁移；不写机械复刻实现的测试。
5. 完成相关检查后更新任务状态及下一节。没有新变更或失败原因，不反复跑相同全量检查。
6. 汇报实际结果；需要真实环境的步骤写具体，不把所有工作都笼统交回用户。

若获得多 agent 并行开发指令，先按模块指定文件责任范围。`app.js`、`shell.js`、`town.mjs`、`town-store.mjs`、构建入口和本交接页均由一个负责者修改；主 agent 汇总、去重、裁决冲突后合并。没有明确并行安排时顺序开发，避免共享文件冲突。
